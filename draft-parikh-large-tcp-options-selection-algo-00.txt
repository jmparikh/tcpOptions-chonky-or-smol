 A Selection Algorithm for Concurrent TCP Option (SEG-U and SEG-O) Size
                                Requests
            draft-parikh-large-tcp-options-selection-algo-00

Abstract

   [I-D.bonica-tcpm-extended-options] defines an Upgraded TCP Segment
   (SEG-U) which can carry up to 1016 octets of TCP options, by setting
   the Data Offset field to 0, and introducing a "length" field.  Given
   that the TCP-U is designed to be backwards compatible with TCP-O,
   hosts which supports this new TCP-U, are expected to support both
   segment formats, SEG-U and SEG-O.  So, there is a chance, that during
   connection setup, the host receive requests for either.  When such
   requests arrive concurrently (or successively), for what would
   otherwise be the same session, the host must decide which format to
   accept and which to decline.

   This document defines an algorithm for dual-capable hosts to select
   between a TCP-U and a TCP-O when presented with both.  It specifies
   selection inputs, tie-breaking, fallback behaviour, and the
   interaction with the existing TCP state machine.

1.  Terminology

   SEG-U:  Upgraded TCP Segment, as defined in
      [I-D.bonica-tcpm-extended-options].  Marked by Data Offset == 0;
      carries an options region of up to 1016 octets.

   SEG-O:  Original (classic) TCP Segment.  Options region capped at
      40 octets.

   SES-U:  A TCP session in which both peers have agreed to exchange
      SEG-U.

   SES-O:  A TCP session in which both peers exchange only SEG-O.

   TCP-O:  TCP that supports SEG-O.

   TCP-U:  TCP that supports SEG-U.

   Dual-capable host:  A host that implements both SEG-U and SEG-O and
      is willing to establish either kind of session.

   Selection event:  The moment at which a dual-capable host must commit
      to SEG-U or SEG-O for a given (prospective) session.

2.  Introduction

   The Upgraded TCP Segment (SEG-U) format defined in
   [I-D.bonica-tcpm-extended-options] raises the TCP options ceiling
   from 40 octets to 1016 octets by repurposing the Data Offset field: A
   value of zero marks a segment as SEG-U rather than classic TCP (SEG-
   O).  Legacy stacks reject dataofs < 5 and therefore drop SEG-U
   silently, giving the format implicit backwards compatibility.

   Hosts that implements both SEG-U and SEG-O can, in the course of
   normal operation, be offered either kind of session.  In some
   deployments the same peer (or two peers acting on behalf of the same
   application) may present both a SEG-U and a SEG-O initiation for what
   the host would treat as a single session.  Without a procedure, the
   outcome is implementation-dependent and may vary between stacks,
   defeating the interoperability goals of
   [I-D.bonica-tcpm-extended-options].

   This document specifies a deterministic selection algorithm for such
   hosts.  It does not change the SEG-U or SEG-O wire formats and does
   not alter the classic TCP three-way handshake beyond the point at
   which the host commits to one format or the other.
